# CI/CD и окружения

## CI

Workflow `CI` (`.github/workflows/ci.yml`) запускается на каждый pull request и push в `main`:

1. `spotlessCheck` проверяет форматирование.
2. `build` собирает проект и запускает тесты. Тесты поднимают PostgreSQL в Testcontainers и применяют все миграции Flyway, поэтому сломанная миграция роняет CI.
3. Проверяется, что собирается Docker-образ.

## Окружения

| Окружение | Когда разворачивается | Профиль Spring |
|-----------|-----------------------|----------------|
| `dev`     | каждый push в `main` | `dev` |
| `stage`   | тег `v*` (например, `v0.1.0`) или вручную: Actions → Deploy → Run workflow | `stage` |

Workflow `Deploy` собирает образ, публикует его в `ghcr.io/trkpo/goals_app_backend` с тегом SHA коммита и по SSH обновляет сервер окружения: `docker compose pull && up -d`. На сервере работают три контейнера: `app`, `db` (PostgreSQL) и `caddy`. Caddy сам выпускает и продлевает сертификат Let's Encrypt, включает HTTPS и редирект с HTTP (`NF_Sec_3`).

Если окружение не настроено совсем, деплой пропускается с предупреждением и CI не падает. Если задана только часть значений, деплой падает сразу и называет недостающие. Весь деплой ограничен 15 минутами, ожидание готовности контейнеров — двумя.

## Настройка окружения

**Сервер.** Linux с Docker и плагином Compose. Открыты порты 80 и 443. DNS-запись домена указывает на сервер. Пользователь для деплоя входит в группу `docker` и может писать в `/opt/goals-app`.

**GitHub.** Settings → Environments → `dev` / `stage`.

Секреты (Secrets):

| Имя | Что это |
|-----|---------|
| `SSH_HOST` | адрес сервера |
| `SSH_USER` | пользователь для деплоя |
| `SSH_PRIVATE_KEY` | приватный ключ, публичная часть — в `~/.ssh/authorized_keys` на сервере |
| `SSH_KNOWN_HOSTS` | вывод `ssh-keyscan <SSH_HOST>` |
| `DB_PASSWORD` | пароль PostgreSQL; без апострофа, обратной косой черты и переводов строк, остальные символы допустимы |
| `AUTH_JWT_SECRET` | необязательный ключ подписи JWT, отдельный для каждого окружения, вывод `openssl rand -base64 32` |

Переменные (Variables):

| Имя | Что это |
|-----|---------|
| `DOMAIN` | домен окружения, например `stage.goals.example.com` |
| `APP_URL` | необязательная ссылка на странице деплоя, например `https://stage.goals.example.com`; без неё ссылки просто не будет |

Для `stage` стоит включить Required reviewers, чтобы деплой шёл только после подтверждения.

## Что должно быть на сервере и в базе

- Образ приложения публикуется с тегом, равным SHA коммита; его же получает compose на сервере. Старые образы старше недели удаляются при каждом деплое.
- Healthcheck приложения задан и в `Dockerfile`, и в `deploy/compose.yaml`: от него зависит запуск Caddy. Проверка readiness включает доступность базы.
- Миграции не требуют прав суперпользователя и расширений PostgreSQL, поэтому подойдёт и управляемая база. Если понадобится расширение, укажите это здесь.

## Секреты

В репозитории секретов нет. На сервере файл `.env` создаёт workflow с правами `600`. Для локального запуска скопируйте `.env.example` в `.env`; этот файл в `.gitignore`.

## Отправка писем с кодами

Сервис `VerificationMail` отправляет письма подтверждения e-mail и восстановления пароля. Обработчик отправляет письмо после фиксации транзакции с кодом. Результат `false` означает, что SMTP не принял письмо или не настроен. Регистрация сохраняет созданную учётную запись и может вернуть `email_confirmation_sent: false`. Публичный ответ восстановления должен оставаться одинаковым для существующего и неизвестного адреса.

Для локального Docker Compose скопируйте параметры SMTP из `.env.example` в `.env`. На стенде с Docker Compose 2.30 или новее задайте их в отдельном `/opt/goals-app/smtp.env` с правами `600`. Workflow деплоя сохраняет этот файл между запусками. В `smtp.env` пишите значения как `ИМЯ=значение` без внешних кавычек. Нужны `SPRING_MAIL_HOST`, `SPRING_MAIL_PORT`, `SPRING_MAIL_USERNAME`, `SPRING_MAIL_PASSWORD` и `MAIL_FROM`. На стендах используйте SMTP с STARTTLS и аутентификацией. `SMTP_AUTH=false` и `SMTP_STARTTLS=false` подходят для локального SMTP-приёмника. Без настроенной почты приложение запускается, готовность проверяется по базе.
